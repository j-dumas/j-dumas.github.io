Nexus-Corp

Info
CategoryWeb
DescriptionYou’ve gained a foothold on Nexus Corp’s internal network. Enumerate the host and get access to the /admin endpoint where the flag resides.
EndpointProvided by the platform, port 3000
FlagHFCTF{spr4y_1d0r_f0rg3ry_fu1l_chain}

TL;DR

The dashboard is accessible with a guessable cookie name, trusts a client-forged JWT’s role claim, and the key-rotation scheme accepts a kid header pointing at an old, leaked signing key. Any forged token can sign in as admin.

Summary

Looking at the webpage, I was met with a login page and no information about any user. Following the description of the challenge, I enumerated the host and found an FTP service where I could get files about employees and details about the JWTs used on the site. Forging a new token I logged in and found a dashboard page with javascript code to read the token. I modified the token further and logged in as the admin, giving access to the admin page and the flag.

First Look

First things first, trying the /admin endpoint returned a 401 Unauthorized. The given endpoint returned a login page with nothing interesting in the source code. So I followed the advice of the description.

Dead Ends

With some credentials and open ports in hand, I tried three routes that failed. Here’s why.

PostgreSQL

The first thing that jumped to my mind was the database mentioned in lines 4-8 of the backup json file. The port 5432 is usually reserved for PostgreSQL, so I confirmed it quickly.

1$ nmap -sV -sC -p 5432 TARGET_IP
2...
3PORT     STATE    SERVICE    VERSION
45432/tcp filtered postgresql

As clearly indicated by the backup file and hinted by the filtered state of the port, the database was only accessible locally. I realized this after running

1$ psql -h TARGET_IP -p 5432 -U hr_admin -d hr_portal -W

to try to connect to the database with no success.

SSH

Maybe I could try to connect using SSH to the machine and find more info about the flag. After all, there was at least one SSH port open.

1$ ssh TARGET_IP                       
2...
3kali@TARGET_IP: Permission denied (publickey).

The opened port 22 needed a public key, so no chance of connection there. There was another SSH port opened on the machine, though. Being curious of what EtherNetIP-1 is supposed to be, I scanned the port 2222, and obviously it was just another SSH service.

1$ nmap -sV -sC -p 2222 TARGET_IP
2...
3PORT     STATE SERVICE VERSION
42222/tcp open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.18 (Ubuntu Linux; protocol 2.0)
5| ssh-hostkey: 
6|   256 ... (ECDSA)
7|_  256 ... (ED25519)
8Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel

This one required a password and not a public key, but after trying the passwords found in the backup on line 8 and onboarding guide on line 11 combined with the username format of line 4 and the list of employees, I had no success.

Note

I did also try to just connect to the login page using the username format and default password, to no success here either.

Solution

  1. Forge a session cookie to reach /dashboard.

    I added the cookie from line 17 of the backup file to value admin to try and maybe get a valid connection.

  2. Read the dashboard’s javascript.

     1<script>
 2        async function loadProfile() {
 3            const cookies = ...
 4
 5            const token = cookies.nexus_session;
 6            if (!token) {
 7                window.location.href = '/';
 8                return;
 9            }
10
11            try {
12                const payload = ...
13
14                if (payload.role === 'admin') {
15                    document.getElementById('admin-link').style.display = 'inline';
16                }
17
18                // Fetch our profile
19                const res = await fetch(`/api/employee/${payload.employee_id}`);
20                ...
21            } ...
22        }
23        ...
24        async function viewProfile(id) {
25            // VULN: IDOR - player can modify this ID in DevTools/intercept
26            const res = await fetch(`/api/employee/${id}`);
27            ...
28        }
29        ...
30    </script>

    It seems from line 12 that having any value in the nexus_session cookie would let us access the dashboard page. However, the rest of the dashboard was empty due to not having a valid employee_id to fetch the correct information (line 19).

    Dead End

    The comment on line 25 was another detour. Being able to access the employee by altering the ID in the network tab and resending the request would reveal nothing useful that I did not already have in the files found in the FTP dump.

  3. Forge a JWT with alg: HS256, role: admin, employee_id: 1001, signed with the leaked key from the FTP dump.

    1{
2  "alg": "HS256",
3  "typ": "JWT",
4}
5{
6  "role": "admin",
7  "employee_id": 1001,
8}
9n3xus_c0rp_s3cr3t_k3y_2024!

    The token uses the employee_id of the admin found in the csv file to try and connect as a valid admin.

  4. First attempt fails.

    The token was rejected. What I had missed was line 4 and 5 of the todo file: the token needed the kid header.

    The kid Header

    Since the JWT signing was moved to a file-based key system as mentioned on line 4, it meant that the token needed to mention which key was used. The server had now an old signing key from line 7 and 8 of the todo file, and a new one mentioned on line 14 of the backup file.

    The kid header is an optional header used to indicate which key was used when signing the token.

  5. Add kid: old to the token header and resign.

     1{
 2  "alg": "HS256",
 3  "typ": "JWT",
 4  "kid": "old",
 5}
 6{
 7  "role": "admin",
 8  "employee_id": 1001,
 9}
10n3xus_c0rp_s3cr3t_k3y_2024!

  6. Visit /admin from the link added with line 14 to 16 of the javascript code on the dashboard

    This returned the flag on the /admin page.

Takeaways

Vulnerability

  • Key rotation without revocation of the old key defeats the whole point of rotating.
  • The kid header can be used in an attack, it’s not just metadata.

Methodology

  • Always check FTP servers when open.
  • A comment with a VULN isn’t always the intended path.
