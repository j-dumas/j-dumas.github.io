Nexus-Corp

Info
CategoryWeb
DescriptionYou’ve gained a foothold on Nexus Corp’s internal network. Enumerate the host and get access to the /admin endpoint where the flag resides.
Endpoint15.223.25.67:3000
FlagHFCTF{spr4y_1d0r_f0rg3ry_fu1l_chain}

Summary

We are met with a login page and no information about any user. Following the description of the challenge, we enumerate the host and find a FTP service where we can get files about employees and details about the JWTs used on the page. Forging a new token we login and find a dashboard page with javascript code to read the token. We modify the token further and are not logged in as the admin, giving us access to the admin page and the flag.

The function loadProfile from line 4 is called on line 97, so let’s start with it. It seems from line 12 that having any value in the nexus_session cookie would let us access the dashboard page. However, the rest of the dashboard was empty due to not having a valid employee_id to fetch the correct information (line 26). I needed to forge a valid JWT token first, then add the admin role as specified in lines 21-23.

Warning

The comment on line 74 was another detour. Being able to access the employee by changing the ID in the network tab and resending the request would reveal nothing useful that I did not already have in the files found in the FTP dump.

From line 16 of the backup I knew the algorithm, and from line 14 of the todo file I knew the signing key. I tried using this token:

1{
2  "alg": "HS256",
3  "typ": "JWT",
4}
5{
6  "role": "admin",
7  "employee_id": 1001
8}
9n3xus_c0rp_s3cr3t_k3y_2024!

It did not work at first. What I had missed was line 11 et 13 of the todo file. The token needed the kid header.

The kid Header

Since the JWT signing was moved to a file-based key system as mentionned on line 10, it meant that the token needed to mention which key was used. The server had now an old signing key from line 13 and 14 of the todo file, and a new one mentionned on line 18 of the backup file.

The kid header is an optional header used to indicate which key was used when signing the token.

I reforged the token using

 1{
 2  "alg": "HS256",
 3  "typ": "JWT",
 4  "kid": "old"
 5}
 6{
 7  "role": "admin",
 8  "employee_id": 1001
 9}
10n3xus_c0rp_s3cr3t_k3y_2024!

with the employee_id of the admin found in the csv file. Not only did it add the link to the /admin page, but I was also authorized because I was the correct employee. Following the link gave me the flag.
