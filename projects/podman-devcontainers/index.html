Podman Development Containers

Part of my dotfiles

Summary

I am adding a base Containerfile (Dockerfile) and a script to create Podman containers with images based on the base Containerfile to create development environments as containers. It came from wanting DevContainers without having to use VSCode (I know there are Neovim features, but still…). I also looked at Distrobox, but I wanted more isolation for my home directory.

Goal

The goal of this project is to learn containerization and Podman, but mostly have a working and clean development environment for developing other projects without installing dependencies on my host system. I also wanted the possibility to have a base environment with my tools that I can add to for specific projects.

Content

Here is the base Containerfile based on Arch Linux. I mostly install needed packages and create a user and a nice prompt.

 1FROM archlinux:latest 
 2LABEL Description="Base development env" 
 3
 4## Installed needed development packages
 5RUN pacman -Syu --noconfirm \
 6    base-devel \
 7    zsh \
 8    neovim \
 9    git \
10    wget 
11
12RUN pacman -Scc --noconfirm 
13
14## Create non root user
15RUN useradd -m -s /usr/bin/zsh jdumas
16USER jdumas
17
18## Initialize folders so they are not root owned on mount
19RUN mkdir /home/jdumas/.local && mkdir /home/jdumas/.config
20
21ENV HOME /home/jdumas
22ENV PROMPT="%F{##a6e3a1}%n%f@%F{##89b4fa}%m%f:%F{##fab387}%~%f $ "
23
24WORKDIR /home/jdumas/src
25CMD ["/usr/bin/zsh"]

Then, to create the container, I use the following script. It takes a flag (-n) to tell the script that we want to use the base image for the container (otherwise we need a new Containerfile for dependencies additions). It also takes a name for the container and the optional path to the project folder to mount it in the container to work on it. It basically parses arguments, creates images and creates a container with the appropriate volumes.

 1##!/usr/bin/env bash
 2
 3BASE_IMG_NAME="devenv"
 4NO_NEW_IMG=false
 5
 6## Order of parameters :
 7##   1. flag to use base img for the container
 8##   2. name
 9##   3. path to project (to share folder)
10usage() {
11    echo "Usage: devenv [-n for no new image] <container name> [project path]"
12}
13
14## Parse argument -n and -p
15while getopts "np:" opt; do 
16    case ${opt} in 
17        n) NO_NEW_IMG=true;;
18        p) PORTS="127.0.0.1:$OPTARG";; ## Stay on localhost
19    esac
20done
21shift $(($OPTIND - 1))
22
23NAME=$1
24PROJECT_PATH=$(realpath ${2:-$(pwd)})
25
26if [ -z $NAME ]; then
27    usage
28    exit 1
29fi
30
31## Create base image
32if ! podman image exists $BASE_IMG_NAME; then
33    podman build -f ~/BaseEnvContainerfile -t devenv .
34fi
35
36## Create other image if needed
37if [ $NO_NEW_IMG = true ]; then
38    IMG_NAME=$BASE_IMG_NAME
39else 
40    IMG_NAME=$NAME
41    podman build -f $PROJECT_PATH/EnvContainerfile -t $NAME $PROJECT_PATH
42fi
43
44## Create container with correct image, volumes and namespace
45CMD="podman start -t --name $NAME \
46    --userns=keep-id \
47    -v $HOME/.config/nvim:/home/jdumas/.config/nvim \
48    -v $HOME/.local/dev/nvim-container-share:/home/jdumas/.local/share/nvim \
49    -v $PROJECT_PATH:/home/jdumas/src \
50    -h $NAME"
51
52if [[ -n "$PORTS" ]]; then
53  CMD="$CMD -p $PORTS"
54fi
55
56CMD="$CMD $IMG_NAME"
57eval $CMD

For example, a Containerfile using the base would be called EnvContainerfile and would look like :

 1FROM devenv
 2LABEL Description="Game Theory env"
 3
 4USER root
 5
 6RUN pacman -Syu --noconfirm \
 7    graphviz
 8
 9RUN pacman -Scc --noconfirm 
10
11USER jdumas

This is the Containerfile for a game theory project using Graphviz to display trees. I would create the container by calling the script like this from the project directory :

1devenv tree_viewer .

I can then start it with

1podman start -ia tree_viewer

I can also connect multiple times with

1podman exec -it mycontainer /bin/zsh
