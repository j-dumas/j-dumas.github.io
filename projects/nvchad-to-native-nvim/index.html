Moving from NvChad to Native Neovim 0.12

Part of my dotfiles

Summary

I’ve wanted for a while now to move from NvChad to a more simple and personalized Neovim config. I thus decided to redo all my config in the new Neovim 0.12 from scratch by readding only what I need and throwing out the rest, things like mason and mason-lspconfig, lazy, etc.

The Config

What’s Needed?

To transform Neovim into the experience I had with NvChad, i.e. close to a full IDE, I’ll need

  • Colorscheme
  • Statusline
  • Tree
  • Highlight
  • Formatter
  • LSP
  • File picker/live grep
  • Autocompletion
  • A Git client to not rely on switching tmux panes for lazygit
  • Linter
  • Debugger

NeoTree: A File Viewer

I’m used to having a file viewer in the side bar and did not really want to use netrw, so I decided to try neo-tree. I added nvim-window-picker for picking a specific window when opening a file instead of opening in the last one. I added nicer colors for the window picker because the default was bright green. It’s now red with a transparent background. Finally I changed the mappings to always ask which window to open a file when there are splits.

Conform: A Formatter

I decided to use conform to invoke formatters in my code and set their settings. I started by configuring stylua to then format my config files correctly and thus test if everything works.

 1vim.pack.add({
 2    "https://github.com/stevearc/conform.nvim",
 3})
 4
 5require("conform").setup({
 6    formatters_by_ft = {
 7        lua = { "stylua" },
 8    },
 9    default_format_opts = {
10        lsp_format = "fallback",
11    },
12    formatters = {
13        stylua = {
14            prepend_args = { "--indent-type", "Spaces" },
15        },
16    },
17})
18
19vim.keymap.set("n", "<leader>fm", function()
20    require("conform").format()
21end, { desc = "Format file" })

Installing tools

I mentioned I wanted to get away from mason to install tools like LSPs and formatters. I landed on mise to install the tools I need on my system and get them in the $PATH so that Neovim can find them. It works just like using npm or pip, but with the recent security track record of the former, I did not want to install my tools with it.

You can install tools like stylua with mise use -g stylua and lua_ls with muse use -g lua-language-server.

LSPs

Neovim’s native lsp is powerful, but I still like to have default configs since they are not yet in nvim. So I installed nvim-lsp-config for defaults that I can extend.

I also decided to change the keymaps for something more intuitive to me, like goto definition (gd), or code actions (ca) or rename (rn) like it was used in NvChad.

Then, I enabled the LSPs I wanted after having installed them with either mise, pip or dnf. I decided to let pylsp manage the linters and formatters since it seemed to simpler to let them work together as intended by the devs, as opposed to C where I’ll add clang-format and clang-tidy. Later I’ll add ltex_plus to edit Latex files.

I also added virtual lines to show error diagnostic under the errors. We’ll see if I keep it or if it is too cluttering.

Finally, I added nvim-file-operations to implement the events emitted by the file manager so that server that can will update import statements and paths.

 1vim.pack.add({
 2    "https://github.com/neovim/nvim-lspconfig",
 3})
 4
 5local map = vim.keymap.set
 6
 7vim.api.nvim_create_autocmd("LspAttach", {
 8    callback = function(args)
 9        local opts = function(desc)
10            return { buffer = args.buf, desc = "LSP: " .. desc }
11        end
12
13        -- Navigation
14        map("n", "gd", vim.lsp.buf.definition, opts("Go to Definition"))
15        map("n", "gD", vim.lsp.buf.declaration, opts("Go to Declaration"))
16        map("n", "gi", vim.lsp.buf.implementation, opts("Go to Implementation"))
17        map("n", "gr", vim.lsp.buf.references, opts("Go to References"))
18
19        -- Actions
20        map("n", "<leader>rn", vim.lsp.buf.rename, opts("Rename"))
21        map({ "n", "v" }, "<leader>ca", vim.lsp.buf.code_action, opts("Code Action"))
22
23        -- Diagnostics
24        map("n", "<leader>df", vim.diagnostic.open_float, opts("Show Diagnostic"))
25        map("n", "<leader>dn", function()
26            vim.diagnostic.jump({ count = 1, float = true })
27        end, opts("Next Diagnostic"))
28        map("n", "<leader>dp", function()
29            vim.diagnostic.jump({ count = -1, float = true })
30        end, opts("Previous Diagnostic"))
31        map("n", "<leader>dl", vim.diagnostic.setloclist, opts("Diagnostics List"))
32    end,
33})

Fzf-Lua: A File Picker

I installed fzf-lua instead of Telescope for the speed. I then set it up with the commands I used the most in NvChad, namely finding files, finding in all files starting from home, finding recent files and live_grep to find words in files in the project.

 1vim.pack.add({ "https://github.com/ibhagwan/fzf-lua" })
 2
 3local fzf = require("fzf-lua")
 4fzf.setup({})
 5
 6local opts = function(desc)
 7    return { desc = "FZF: " .. desc }
 8end
 9
10local map = vim.keymap.set
11map("n", "<leader>ff", fzf.files, opts("Find files"))
12map("n", "<leader>fa", function()
13    fzf.files({ cwd = "~" })
14end, opts("Find all files"))
15map("n", "<leader>fo", fzf.oldfiles, opts("Find recent files"))
16map("n", "<leader>fw", fzf.live_grep, opts("Live grep"))
17map("n", "<leader>fk", fzf.keymaps, opts("Find keymaps"))
18map("n", "<leader>fb", fzf.buffers, opts("Find buffers"))

Blink: Autocompletion

I used blink, the newer, faster completion plugin, to have completion and snippets sourced from LSPs. I modified a bit the keymaps to my liking using enter to accept a completion and tab to move inside the list. Finally, I added the capabilities of blink to the LSPs.

 1vim.pack.add({ { src = "https://github.com/Saghen/blink.cmp", version = "v1" } })
 2
 3local blink = require("blink.cmp")
 4blink.setup({
 5    keymap = {
 6        preset = "enter",
 7
 8        ["<Tab>"] = { "select_next", "snippet_forward", "fallback" },
 9        ["<S-Tab>"] = { "select_prev", "snippet_backward", "fallback" },
10
11        ["<Up>"] = false,
12        ["<Down>"] = false,
13        ["<C-p>"] = false,
14        ["<C-n>"] = false,
15    },
16    completion = {
17        list = {
18            selection = { preselect = false, auto_insert = true },
19        },
20    },
21})
22
23vim.lsp.config("*", {
24  capabilities = blink.get_lsp_capabilities(),
25})

Git Client

I added gitsigns to show lines that have been changes in the buffers and added the lazygit nvim plugin to toggle a floating Lazygit terminal. I’m already used to Lazygit, but this plugins makes it so I can 1) use it in the same window and 2) open the files in conflicts inside the same Neovim instance.

1vim.pack.add({
2    "https://github.com/lewis6991/gitsigns.nvim",
3    "https://github.com/kdheepak/lazygit.nvim",
4})
5
6vim.keymap.set("n", "<leader>g", "<cmd>LazyGit<cr>", { desc = "Open Lazygit" })
